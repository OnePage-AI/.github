# [트러블슈팅] 끊김 없는 온보딩: 중간 로그인 시 상태 보존(State Preservation) 기술

## 1. 문제 상황
사용자가 비회원 상태에서 강의 자료를 업로드하고 분석 범위(페이지 선택)를 정교하게 설정한 뒤, 실제 분석을 시작하려는 시점에 로그인이 필요한 경우가 많습니다. 초기 시스템에서는 상단 네비바의 로그인 버튼을 누르면 페이지가 새로고침되면서 **기존에 업로드한 파일과 선택한 분석 범위 설정이 모두 초기화**되어 사용자가 처음부터 다시 작업을 시작해야 하는 큰 불편함이 있었습니다.

## 2. 해결 시도 및 새로운 병목
*   **시도 1: LocalStorage 저장**: 업로드된 파일의 메타데이터와 페이지 선택 범위를 로컬 스토리지에 임시 저장한 뒤 로그인 후 복원.
*   **병목**: 파일 데이터(File Object) 자체는 보안 및 브라우저 정책상 스토리지에 직접 저장할 수 없으며, 로그인 리다이렉트 과정에서 메모리 상의 파일 객체가 소멸되는 한계가 있었습니다.

## 3. 내부 메커니즘 분석 및 재설계

### 3.1. Auth-Forwarding 구조 도입
사용자의 작업 상태(Upload State)를 관장하는 `Context`를 설계하고, 로그인 버튼 클릭 시 현재 작업 중인 `State`를 URL 파라미터나 전용 세션 브리지에 인코딩하여 전달하는 방식을 취했습니다.

### 3.2. 영속적 파일 프리로드(Pre-load)
로그인 유도 팝업이 뜨더라도 뒷단의 업로드 프로세스는 백그라운드에서 중단 없이 유지되도록 **Modal-First 인증 흐름**으로 전환했습니다. 페이지 전체 이동이 아닌 모달 기반 로그인을 통해 React 상태를 메모리에 보존한 상태로 인증 정보만 동적으로 업데이트합니다.

## 4. 최종 안정화 및 결과
*   **매끄러운 흐름**: 사용자는 로그인을 마친 직후, 이전에 선택했던 페이지 범위와 업로드된 파일이 그대로 유지된 화면으로 돌아와 즉시 분석을 시작할 수 있습니다.
*   **이탈률 감소**: 회원가입/로그인 과정에서 발생하는 작업의 재반복을 제거하여 온보딩 과정에서의 사용자 이탈률을 유의미하게 낮췄습니다.

기술적 완성도는 단순한 기능 구현이 아니라, **사용자가 의도치 않게 들여야 하는 노력을 얼마나 줄여주느냐**에서 결정됨을 배웠습니다.
