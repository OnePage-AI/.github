# Cloud Run 비용 최적화 기록

## 문제 상황

운영 중 Cloud Run 비용이 사용량 대비 높게 발생하는 현상이 확인되었습니다. 요청 수 자체보다 상시 실행되는 인스턴스 설정이 비용을 만들고 있었고, 특히 AI 분석 서비스가 가장 큰 비중을 차지했습니다.

## 원인

AI 분석 서비스는 API 서버와 백그라운드 작업 워커가 같은 컨테이너 안에서 함께 실행되는 구조입니다. 과거에는 분석 작업 안정성과 콜드 스타트 방지를 위해 최소 인스턴스를 1개 유지했습니다.

이 설정은 안정성에는 도움이 되지만, 요청이 없는 시간에도 CPU와 메모리 비용을 계속 발생시킵니다. 특히 AI 서비스는 메모리 할당이 크기 때문에 상시 인스턴스 비용이 빠르게 누적되었습니다.

## 조치

가장 큰 비용 원인을 먼저 차단하기 위해 AI 분석 서비스의 최소 인스턴스를 0으로 조정했습니다. 다만 분석 작업이 실행되는 동안 백그라운드 워커가 CPU를 사용할 수 있도록 CPU 항상 할당 설정은 유지했습니다.

```text
변경 전: 최소 인스턴스 1개 유지
변경 후: 최소 인스턴스 0개, 실행 중 CPU 보장 유지
```

이 변경으로 유휴 시간의 고정비를 줄이면서도, 분석 작업이 실제로 시작된 뒤에는 기존 worker 실행 방식을 유지할 수 있습니다.

## 운영 기준

이번 변경은 비용 절감 우선 조치입니다. 분석 작업이 대기 상태에 오래 머물거나, 결과 저장이 지연되거나, 콜드 스타트가 사용자 경험을 크게 해치면 최소 인스턴스를 다시 1개로 되돌립니다.

장기적으로는 API 서버와 백그라운드 워커를 분리해, 사용자 요청을 받는 서버와 장시간 분석 작업을 처리하는 실행 단위를 각각 다른 비용 구조로 운영하는 방향을 검토합니다.

## 배운 점

서버리스 환경에서도 최소 인스턴스와 CPU 할당 설정을 어떻게 두느냐에 따라 사실상 상시 서버처럼 비용이 발생합니다. 분석 작업 안정성을 위해 켜 둔 설정이 비용 측면에서는 고정비로 전환되므로, 안정성 기준과 비용 기준을 함께 문서화하고 주기적으로 재검토해야 합니다.
