# [트러블슈팅] "Design is Modern, Data is Classic": 마크다운 엔진의 회복 탄력성 확보

## 1. 문제 상황
AI가 생성한 분석 결과물을 사용자에게 보여줄 때, 초기에는 정교한 UI 표현을 위해 모든 데이터를 JSON 객체로 구조화하여 전달받았습니다. 하지만 사용자들이 결과를 복사하여 **노션(Notion), 옵시디언(Obsidian)** 등 외부 도구로 가져가려 할 때, UI 장식 요소들이 모두 깨지거나 텍스트 무결성이 훼손되는 문제가 발생했습니다.

## 2. 해결 시도 및 새로운 병목
데이터 호환성을 위해 "Data is Classic" 원칙에 따라 데이터 규격을 **표준 마크다운(Markdown)** 문자열로 회귀시켰습니다. 그러나 AI(Gemini)가 생성하는 마크다운은 완벽하지 않았습니다.

*   **Sticky Bullets**: 문장 끝에 공백 없이 바로 불렛 기호(`-`)가 붙어 렌더링이 깨짐.
*   **불일치한 공백**: `- 내용`, ` - 내용`, `-내용` 등 불렛 기호 뒤의 공백이 가변적으로 생성되어 계층 구조 인지 실패.
*   **강조 구문 파손**: `**강조(내용)**` 처럼 괄호가 포함된 경우 마크다운 파서가 이를 정확히 닫지 못해 스타일이 뒤섞임.

## 3. 내부 메커니즘 분석 및 재설계
문제를 해결하기 위해 프론트엔드 렌더링 직전에 AI의 실수를 보정하는 **회복 탄력적 전처리기(Resilience Preprocessor)**를 도입했습니다.

### 3.1. 정규표현식 기반 문법 정규화
AI가 생성한 텍스트를 AST(Abstract Syntax Tree) 파싱하기 전, 정규식을 통해 표준 포맷으로 강제 변환합니다.
```typescript
// 예시: 불렛 기호 뒤 공백 강제 삽입 및 Sticky Bullet 방지
const normalized = rawMarkdown
  .replace(/^(\s*)-([^\s])/gm, "$1- $2") // 불렛 뒤 공백 보정
  .replace(/([^\n])\n-/g, "$1\n\n-");   // 문장 끝 불렛 강제 개행
```

### 3.2. 지능형 페이지 참조 칩 (Page Reference Chips)
AI가 텍스트 중간에 남기는 `[Page n]`, `Slide n`, `pg.n` 등 다양한 형태의 페이지 참조를 감지하여, 클릭 시 PDF 해당 페이지로 즉시 이동하는 **인터랙티브 칩**으로 변환하는 로직을 구축했습니다.

## 4. 최종 안정화 및 결과
*   **회복 탄력성**: AI의 사소한 포맷 오류에도 UI 레이아웃이 무너지지 않고 정갈한 학술지 스타일을 유지합니다.
*   **호환성**: "복사하기" 클릭 시 순수 마크다운이 보존되어 외부 도구와의 연동성이 극대화되었습니다.
*   **UX 향상**: 단순 텍스트였던 페이지 번호가 유기적인 내비게이션 도구로 진화했습니다.

단순히 AI에게 "잘 생성하라"고 명령하는 것보다, 시스템이 **불완전한 입력을 수용하고 보정하는 구조**를 갖추는 것이 실제 운영 환경에서 훨씬 더 강력한 안정성을 제공함을 확인했습니다.
