### 1. 문제 상황: "왜 크레딧이 마이너스가 될까?"

![image.png](attachment:8f872e5d-5e29-44f8-829f-eb7efc3fbcf9:image.png)

- **원인:** 분석 완료 후 차감하는 **후불제 방식**의 한계.
- **문제:** 5개 남았을 때 6번 광클하면, 차감 전이라 FE 체크를 모두 통과해버림.
- **결과:** DB 데이터 부정합 및 서버 자원 낭비(Overdraft).

---

### 2. 해결 전략: 낙관적 업데이트 (Optimistic Update)

"일단 깎고, 문제 생기면 돌려준다." 복잡한 예약 시스템 대신 사용자 반응성과 정합성을 모두 잡는 방식을 택했다.

- **FE:** 버튼 클릭 즉시 UI 크레딧 **1** (낙관적 차감).
- **AI BE:** 작업 실패 시 BE 환불 API 호출하여 **+1** (보상 트랜잭션).

---

### 3. 세부 구현 사항

![image.png](attachment:7506f363-34ba-4695-9960-6bd41316b1d5:image.png)

### 3.1. 스프링 백엔드 (`onepage-be`) - 환불 API 구축

- **기능:** `userId`를 받아 크레딧을 안전하게 복구.

```java
// MemberRestController.java
@PostMapping("/usage/refund")
public ApiResponse<Void> refundUsageCount(@Valid @RequestBody RefundUsageRequest request) {
    memberCommandUseCase.refundUsageCount(request.getUid(), request.getTaskId());
    return ApiResponse.onSuccess(null);
}
```

### 3.2. AI 백엔드 (`onepage-ai`) - 환불 호출 로직

- **성공 시:** 기존 차감(decrement) API 호출 제거 (FE에서 이미 처리됨).
- **실패 시:** `except` 블록에서 환불 API 호출.

```python
# worker.py (수정 후 로직)
try:
    # AI 분석 수행...
except Exception as e:
    # 실패 시 환불 API 호출
    async with httpx.AsyncClient() as client:
        await client.post(f"{BE_URL}/v1/members/usage/refund", json={"uid": uid, "taskId": task_id})
    # 이후 에러 처리...
```

### 3.3. 프론트엔드 (`onepage-fe`) - 즉각적인 UI 피드백

- **AuthContext:** 크레딧 상태를 직접 제어할 수 있게 `setAvailableCredits` 노출.
- **Workspace:** 작업 요청 직전 상태값 변경.

```tsx
// page.tsx
const generate = async () => {
  if (availableCredits > 0) {
    setAvailableCredits(prev => prev - 1); // 즉시 반영
    startAnalysisTask(payload);
  }
};
```

### 4. 개선 결과 및 기대 효과

1. **초과 인출 원천 봉쇄:** 사용자가 가진 크레딧만큼만 작업을 던질 수 있음.
2. **UX 향상:** 버튼 누르자마자 숫자가 줄어들어 시스템이 즉각 반응한다는 느낌을 줌.
3. **정합성 유지:** 최종 완료 시 `fetchCredits()`로 백엔드 실데이터와 다시 동기화하여 오차 제거.
