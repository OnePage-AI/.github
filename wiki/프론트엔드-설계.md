# 프론트엔드 설계

## 역할

웹 애플리케이션은 자료를 분석하는 기능뿐 아니라 사용자가 결과에 도달하기까지의 판단 부담을 줄이는 역할을 담당합니다. Next.js와 TypeScript 기반으로 랜딩, 고객센터, 로그인, 라이브러리, 작업 화면을 구성합니다.

## 작업 화면

데스크톱에서는 원본 자료와 AI 결과를 함께 확인할 수 있는 구조를 유지합니다. 모바일에서는 같은 정보를 좁은 화면에 단순 축소하지 않고, 사용자가 현재 필요한 내용에 집중할 수 있도록 결과와 원본 확인 흐름을 정리합니다.

| 화면 맥락 | 설계 판단 |
| --- | --- |
| 새 자료 생성 | 학습 목적, 설정, 업로드, 분석 시작의 순서를 명확하게 보이게 구성 |
| 결과 확인 | 작은 화면에서는 결과 읽기를 우선하고 원본으로 이동할 수 있게 구성 |
| 라이브러리 | 저장된 자료를 빠르게 찾을 수 있도록 모바일 카드 정보 밀도를 조정 |
| 긴 표 결과 | 내용을 억지로 압축해 글자가 깨지지 않도록 읽을 수 있는 폭과 스크롤을 제공 |

## 로그인 연속성

로그인이 필요한 시점에도 사용자가 이미 선택한 자료와 설정 흐름을 잃지 않도록 하는 것이 중요합니다. 로그인 이후 분석 과정으로 자연스럽게 이어지는 경험을 설계 기준으로 삼습니다.

## 공통 UI 원칙

- 모바일에서는 핵심 CTA가 메뉴 안에 숨지 않도록 합니다.
- 모바일 선택 영역은 충분한 터치 범위와 읽을 수 있는 줄바꿈을 유지합니다.
- 데스크톱의 정보 구조와 브랜드 톤은 유지하면서, 모바일 조작 방식은 화면 폭에 맞춰 정리합니다.
